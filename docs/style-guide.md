# 翻译规范

所有脚本共用这份规范，保证不同站点、不同贡献者的译文风格一致。

## 翻什么，不翻什么

**翻译**：界面文案，包括按钮、菜单、标签、表头、提示、弹窗、表单校验提示、空状态、确认对话框。

**不翻译**：

- 品牌名和产品名（OpenRouter、Stripe、GitHub、Google 等）
- 模型名称和模型 slug、代码、命令、API 密钥、网址
- 通用缩写：API、SDK、JSON、HTTP、URL、ID 等
- 快捷键字符、货币符号、数字
- 用户输入的内容、提示词与日志正文等第三方和用户数据

## 风格

- 面向开发者和技术用户，简洁直接，不用翻译腔。
- 按钮用动词短语：「保存」「创建密钥」「复制」，不写成「点击此处保存」。
- 第二人称统一用「你」，不用「您」。
- 译文宽度不要比原文长太多。按钮、标签、表头尤其要短，窄屏下需要验证没有溢出或被截断。

## 标点与排版

- 使用全角中文标点：，。：；？！、（）。
- 引号使用弯引号“ ”。
- 中文与英文、数字之间加一个半角空格：`API 密钥`、`3 天前`、`共 12 项`。
- 变量与占位符原样保留，只允许按中文语序调整位置：`{n}`、`%s`、`{{name}}`。
- 省略号用「…」。

## 多义词

同一个英文词在不同语境意思不同（例如 Reset、Limit、Key、Credit 的名词和动词用法），按语境译，不要全站统一成一个译法。需要时在脚本里按页面路径区分，并在下面的表里注明。

## 通用术语表（初稿）

## 变更流程

- 新增术语：在 PR 里加进上表，状态写「初稿」。
- 修改已有译法：在 PR 里说明理由，并同步修改所有受影响的脚本。
- 危险操作（删除、撤销、付款、清空）相关的按钮和提示，译文必须与原文含义完全一致，评审时重点检查。
